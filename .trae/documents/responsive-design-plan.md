# 移动端及全端响应式适配计划

## 摘要
本计划旨在对大模型测评平台（`frontend` 目录）的所有页面进行全面的响应式改造，使其能够完美适配移动端（手机）、iPad端（平板）和电脑端（桌面）。我们将遵循“移动端优先（Mobile-first）”的 Tailwind CSS 编写原则，不改变现有核心业务逻辑，仅通过调整布局结构、类名和少量交互组件来实现多端适配。

## 当前状态分析
目前系统的 UI 主要面向桌面端设计：
- **全局布局 (`Layout.tsx`)**：固定宽度为 256px 的左侧边栏，在移动设备上会严重挤占主内容区。
- **列表页 (`Models.tsx`, `Datasets/index.tsx`, `Evaluations/List.tsx`)**：采用了宽幅的 Table 或水平分布的 Card 布局，在窄屏下会发生内容截断或水平滚动。
- **表单与编排页 (`Datasets/Editor.tsx`, `Evaluations/Create.tsx`)**：输入框和多选面板在移动端缺少合理的纵向堆叠和触控优化。
- **测评详情与对比页 (`Evaluations/Detail.tsx`)**：采用了固定多列 Grid 布局展示模型横向对比，在手机端多列并排会导致文字极度拥挤，完全无法阅读。
- **文档页 (`Document/index.tsx`)**：左右分栏布局，左侧导航栏在小屏下占据过多横向空间。
- **登录页 (`Home.tsx`)**：固定了 `max-w-[360px]`，在超小屏幕上可能边缘过窄。

## 拟议变更 (Proposed Changes)

我们将利用 Tailwind 的断点系统：默认（移动端） -> `md:` (平板, >=768px) -> `lg:` (桌面, >=1024px)。

### 1. 登录页 (`frontend/src/pages/Home.tsx`)
- **宽度适配**：将容器宽度调整为 `w-full px-4 md:max-w-[360px] md:px-6`，确保在手机端充分利用宽度并保留安全边距，而在桌面端保持原有的小巧居中形态。

### 2. 全局布局 (`frontend/src/components/Layout.tsx`)
- **移动端导航栏**：引入一个顶部的移动端导航栏（Top Bar），包含汉堡菜单按钮（Hamburger Menu）和平台 Logo。仅在 `md:hidden` 时显示。
- **抽屉式侧边栏**：
  - 在移动端，侧边栏默认隐藏（或通过状态控制从左侧滑出/作为遮罩层显示）。
  - 在 `md:` 及以上屏幕，恢复为固定的 `w-64` 左侧边栏。
  - 主内容区增加底部的安全内边距（如 `pb-safe`），防止被全面屏手势条遮挡。

### 3. 模型中心与题库中心列表页 (`Models.tsx`, `Datasets/index.tsx`)
- **顶部操作区**：将搜索框和“新增”按钮在移动端改为上下堆叠（`flex-col gap-3`），在 `md:flex-row` 时恢复为左右两端对齐。
- **列表项展示**：
  - 桌面端（`md:table` 或 `md:grid`）：保持现有的多列紧凑展示。
  - 移动端：如果是表格，建议改为堆叠的卡片列表（Card List），每张卡片垂直展示模型/题目名称、状态和操作按钮。

### 4. 对话编排与创建任务页 (`Datasets/Editor.tsx`, `Evaluations/Create.tsx`)
- **布局调整**：表单区域在移动端占满宽度（`w-full px-4`），在桌面端限制最大宽度（`max-w-3xl`）并居中。
- **对话气泡/角色选择**：在 `Editor.tsx` 中，将角色下拉框、输入框和删除/上下移按钮在移动端改为折行显示或更紧凑的 Grid 布局，增大触控响应面积。

### 5. 测评任务列表与详情对比页 (`Evaluations/List.tsx`, `Evaluations/Detail.tsx`)
- **任务列表**：类似于模型列表，移动端使用垂直卡片流，突出状态 Tag 和时间。
- **详情对比页 (核心改造)**：
  - **整体结构**：左侧的“题目切换侧边栏”在移动端移至顶部，作为横向滚动的 Tabs (`flex overflow-x-auto whitespace-nowrap`)。
  - **模型对比矩阵**：
    - 移动端：强制将多列转为单列垂直堆叠 (`grid-cols-1 gap-6`)。每个模型的回复框占据整行，用户向下滚动查看不同模型的结果。
    - 平板端：`md:grid-cols-2`。
    - 桌面端：`lg:grid-cols-3` 或按模型数量自适应。
  - **指标展示**：将耗时、速度等指标在手机端改为紧凑的 Badge 形式排列。

### 6. 协议文档页 (`frontend/src/pages/Document/index.tsx`)
- **导航栏重构**：
  - 移动端：左侧的目录导航变为顶部的横向滚动菜单（`w-full flex overflow-x-auto border-b`）。
  - 桌面端：保持 `md:flex-row` 左右分栏。
- **正文排版**：移动端减小内边距（`px-4 py-6`），缩小主标题字号（`text-2xl md:text-3xl`），保证阅读舒适度。

## 假设与决策 (Assumptions & Decisions)
- **纯 CSS 驱动优先**：为了尽量不破坏现有的 React 状态逻辑，我们优先使用 Tailwind 的响应式类名（如 `hidden md:block`, `flex-col md:flex-row`）来实现适配。
- **状态管理最小化**：对于移动端侧边栏的展开/收起，可能需要在 `Layout.tsx` 中新增一个简单的 `useState(false)` 控制菜单的显示状态。
- **不修改业务接口**：本次改造纯粹为 UI 表现层，不涉及任何与后端 `/api` 的交互修改。

## 验证步骤 (Verification)
实施完成后，需要在浏览器中使用开发者工具（F12）进行以下测试：
1. **iPhone 尺寸 (如 375px)**：验证登录页、移动端顶部导航+抽屉菜单是否正常；所有列表是否转为卡片流；详情页对比矩阵是否变为单列向下滚动；文档页导航是否变为顶部 Tabs。
2. **iPad 尺寸 (如 768px)**：验证侧边栏是否恢复固定显示；列表和对比矩阵是否能合理利用半宽屏幕（如两列并排）。
3. **桌面端尺寸 (>= 1024px)**：验证原有的大屏设计是否完好无损，没有因为移动端代码的加入而变形。
