- **做法**：
  - 左侧保留 1 个输入触点（Target Handle）。
  - 右侧需要渲染**至少 2 个**输出触点（Source Handle），例如分别代表“条件满足（是）”和“条件不满足（否）”。
  - 为了让 React Flow 能区分这多条输出连线，每个 Source Handle 必须配置一个全局唯一的 `id`（例如 `id="true"` 和 `id="false"`）。

### 3. 将新节点注册到画布引擎
- **文件**：[index.ts](file:///workspace/frontend/src/pages/Processes/components/nodes/index.ts)
- **分析**：将编写好的 `ConditionNode` 引入，并在导出的 `nodeTypes` 对象中以 `condition: ConditionNode` 的键值对注册。这样当从侧边栏拖入条件节点时，React Flow 就能正确渲染出带有两个出口的节点。

### 4. 属性面板的配置支持（进阶扩展）
- **文件**：[PropertiesPanel.tsx](file:///workspace/frontend/src/pages/Processes/components/PropertiesPanel.tsx)
- **分析**：当用户在画布上选中“条件判断节点”时，右侧的属性面板需要提供配套的逻辑配置。
- **做法**：
  - 属性面板应该渲染出一套“条件配置器”，例如让用户选择判断字段（金额、工单类型）、判断符（大于、等于、包含）以及判断值。
  - 如果业务更复杂，甚至可以允许用户在属性面板中点击“添加分支”，然后动态去更新 `ConditionNode.tsx` 里的 Source Handle 数量（即动态多分支）。初期实现为了简单，通常写死“是”和“否”两个分支即可。

### 总结
核心实现路径为：**侧边栏增加配置 -> 编写带有“多个 Source Handle”的定制化节点组件 -> 注册到引擎中 -> 属性面板支持条件表达式配置**。
